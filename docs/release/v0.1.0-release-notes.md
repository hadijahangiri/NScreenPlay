# NScreenplay v0.1.0 Release Notes

**Released:** 2026-08-23

> ⚠️ **Pre-release.** This is an early release. Public APIs may change before v1.0. See [Known Limitations](#known-limitations).

---

## Overview

NScreenplay v0.1.0 is the first public release of an AI-native Screenplay Test Automation Framework for .NET.

It provides:

- **A clean Screenplay pattern implementation** for .NET 10
- **First-class Playwright integration** for browser automation
- **Reqnroll (BDD/Gherkin) integration** with proper Actor lifecycle
- **AI agent Skills** teaching agents how to use the framework
- **MCP foundation** for AI agent integration
- **Approval-gated healing** for test maintenance assistance

NScreenplay is primarily a **test automation framework**. The AI capabilities are a differentiator, not a requirement.

---

## New in v0.1.0

### NScreenplay.Core

- **Actor** — scenario-scoped, `IAsyncDisposable`, strongly typed ability retrieval, pre-cancellation checks
- **Ability model** — type-safe registration and retrieval
- **IPerformable / ITask / IInteraction** — composable execution with `CancellationToken`
- **IQuestion\<T\>** — read-only typed queries
- **IConsequence** — extensible verification abstraction
- **Target** — adapter-neutral semantic locators (9 strategies: TestId, Role, Label, Id, CSS, XPath, Text, Placeholder, AltText)
- **Disposal safety** — continues disposing all abilities even if one fails; rethrows first error

### NScreenplay.Playwright

- **BrowseTheWeb** — `IAbility` wrapping `IPage`, auto-closes page on Actor disposal
- **TargetResolver** — maps all 9 locator strategies to Playwright locators
- **Built-in Interactions:** `Click`, `Enter` (FillAsync), `Navigate`, `Select`, `Check`/`Uncheck`
- **Built-in Questions:** `Text`, `Visibility`, `CurrentUrl`, `PageTitle`, `InputValue`

### NScreenplay.Reqnroll

- **NScreenplayHooks** — `[BeforeFeature/AfterFeature/BeforeScenario/AfterScenario]` with clean ordering
- **BrowserManager** — feature-scoped `IBrowser` with fallback to installed Chromium
- **ScenarioActor** — scenario-scoped Context + Page + Actor with `IAsyncDisposable`
- **Parallel scenario isolation** — separate `IBrowserContext` per scenario
- **reqnroll.json** integration — register NScreenplay hooks via `stepAssemblies`

### AI Agent Skills (7)

Instruction-first `SKILL.md` files teaching AI agents the framework:
`screenplay`, `playwright`, `reqnroll`, `test-authoring`, `test-review`, `failure-analysis`, `healing`

### MCP Foundation (NScreenplay.Mcp)

- **11 MCP tools:** discovery, failure analysis, test planning, healing workflow
- **8 MCP resources:** `nscreenplay://framework`, `//architecture`, `//skills`, `//tasks`, `//targets`, `//interactions`, `//questions`, `//context`
- **1 MCP prompt:** `nscreenplay_create_test` (test plan generation)
- **Deterministic engine:** `RequirementAnalyzer` + `TestPlanGenerator` (no LLM required)
- **Rule-based failure analysis:** classifies 6 failure categories with confidence levels
- **Optional `IAiProvider`:** plug in any LLM without changing framework core

### Controlled Healing

- **H-01:** `ByCss("#id")` → `ByTestId("id")`
- **H-02:** `ById("id")` → `ByTestId("id")`
- **7-state proposal state machine** with invalid transition enforcement
- **Approval gate:** AI cannot approve its own proposals
- **Stale detection:** SHA-256 file hash prevents applying proposals to changed files
- **Atomic writes + rollback capture**
- **Path traversal protection**

### Login Sample

- Complete runnable example: Reqnroll + NScreenplay + Playwright
- Self-contained HTML test app (no web server required)
- Demonstrates the full Screenplay workflow end-to-end

## Known Limitations

1. **Chromium only** — `BrowserManager` supports Chromium; Firefox/WebKit planned
2. **Windows tested** — Linux expected to work; macOS unverified
3. **Healing is regex-based** — no AST analysis; may miss multi-line patterns
4. **Global configuration** — `NScreenplayConfiguration` is a set-once singleton
5. **`NSCREENPLAY_WORKSPACE_ROOT` required** for healing file operations
6. **No NuGet published** — packages are built but not yet on nuget.org
7. **Pre-release API stability** — public APIs may evolve before v1.0
